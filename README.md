# nanollm — an optimized LLM inference engine

> **Languages:** **English** · [Português](README.pt-BR.md)

> A from-scratch inference engine that runs **real GPT-2** with the optimizations
> that production engines (TensorRT-LLM, vLLM, llama.cpp) are built on: **KV-cache**,
> **FlashAttention-style fused attention**, **INT8/INT4 weight quantization**, and
> **static batching** — in pure Python/NumPy, with the fused kernels written in
> **Triton** for the GPU. Efficient LLM inference is NVIDIA's core business today;
> this shows the machinery underneath.

```bash
python scripts/download_model.py                       # fetch GPT-2 (124M)
python scripts/generate.py "The future of AI is" --max-new 40
```
```
The future of AI is uncertain. The future of AI is uncertain. The future of AI is
uncertain. ...                       # real GPT-2 124M, generated by this engine
```

## Results (CPU — the NumPy engine)

GPT-2 124M, `scripts/benchmark.py` + `scripts/eval_perplexity.py`:

| Optimization | Metric | Result |
|---|---|---|
| **KV-cache** | decode throughput | **10.0 → 39.1 tok/s (3.9× faster)** |
| KV-cache | latency split | TTFT 58 ms · per-token 24 ms |
| **Static batching** | total throughput | 38 → 50 → **53 tok/s** (batch 1→4→8) |
| **INT8 quant** | perplexity / memory | **18.06 → 18.13** (+0.4%) · 498 → **243 MB** |
| INT4 quant | perplexity / memory | 18.06 → 31.38 · 498 → 201 MB |

![benchmark](results/benchmark.png)
![quantization](results/perplexity.png)

> The headline: **INT8 halves the model with essentially no quality loss**, and
> the **KV-cache gives a 3.9× decode speedup** — the two optimizations that matter
> most for serving. These numbers are from the NumPy engine on CPU; the **Triton
> GPU kernels are measured separately on a Tesla T4** — see *GPU results* below.

## GPU results (Triton kernels, measured on a Tesla T4 / Kaggle)

`bench_gpu.py` exercises the two fused kernels on a real GPU: it checks each
against a PyTorch reference, then times it against baselines. The kernels
**compile, run, and are numerically correct** on real hardware.

**FlashAttention (fused, causal), fp32 — GPT-2 124M shapes (12 heads, head_dim 64):**

| seq len | triton (fused) | naive PyTorch | torch SDPA | correctness |
|--------:|---------------:|--------------:|-----------:|-------------|
| 256  | 0.353 ms | 0.310 ms | 0.210 ms | rel_err 1.2e-7 |
| 512  | 1.090 ms | 0.927 ms | 0.452 ms | rel_err 1.4e-7 |
| 1024 | 2.243 ms | 2.615 ms (**1.2× slower than triton**) | 0.679 ms | rel_err 1.5e-7 |

**INT8 dequant-matmul (fused, MLP GEMM 768→3072), fp32 activations:**

| M | triton (fused) | unfused dequant+mm | fp32 cuBLAS | correctness |
|--:|---------------:|-------------------:|------------:|-------------|
| 256  | 0.242 ms (**1.5× vs unfused**) | 0.366 ms | 0.272 ms | exact |
| 512  | 0.719 ms | 0.627 ms | 0.532 ms | exact |
| 1024 | 1.342 ms | 1.167 ms | 1.091 ms | rel_err 4.7e-7 |

Weight memory: **fp32 → int8 is 4.0× smaller**, held as int8 through the fused path.

> **Honest read:** the kernels are correct on real hardware, and the INT8 path is
> a genuine memory win (4×). On raw speed they're competitive with naive baselines
> but do **not** beat torch's SDPA / cuBLAS — those use fp16 **Tensor Cores**,
> autotuning and software pipelining that these hand-written **fp32** kernels don't
> have yet (the T4 is sm_75; `tl.dot` in fp32 skips the tensor cores entirely).
> Numbers reported as measured — wins and losses. Closing this gap (fp16 + autotune)
> is the top item in *Next steps*.

## Quickstart

```bash
pip install -r requirements.txt              # numpy + safetensors
python scripts/download_model.py             # GPT-2 124M into models/gpt2/

python tests/test_nanollm.py                 # correctness (tokenizer, flash==naive, KV-cache==no-cache, quant, batching)
python scripts/generate.py "Once upon a time" --max-new 40 --temperature 0.8 --top-k 40
python scripts/generate.py "AI is" --quant int8         # quantized weights
python scripts/benchmark.py                  # tok/s, latency, memory  -> results/benchmark.csv
python scripts/eval_perplexity.py            # quality vs quantization -> results/perplexity.csv
python scripts/plot_results.py               # -> results/*.png
python scripts/compare_baseline.py           # vs HuggingFace logits (if transformers installed)

# GPU only (needs an NVIDIA GPU + torch + triton):
python bench_gpu.py                          # Triton kernels: correctness + timings vs PyTorch
```

## Architecture

```
nanollm/
├── tokenizer.py     GPT-2 byte-level BPE, from scratch (vocab.json + merges.txt)
├── loader.py        download + read safetensors -> {name: np.float32}
├── config.py        GPT2Config (124M / 355M / 774M / 1.5B dims)
├── model.py         GPT-2 forward in NumPy + KVCache (pre-LN blocks, GELU, tied head)
├── attention.py     sdpa_naive  +  sdpa_flash (online softmax) — validated equal
├── quant.py         symmetric per-channel INT8/INT4 weight quant (+ INT4 bit-packing)
├── generate.py      sampling + KV-cache decode loop + static batching (left-pad/mask)
├── metrics.py       perplexity, memory report
└── triton_kernels.py  fused FlashAttention + fused INT8 dequant-matmul (Triton, GPU)
```

The model loads weights as a plain `dict` of NumPy arrays; quantization swaps the
big linear weights for `QTensor`s, and the model's `_mm` dispatches transparently
(`x @ W` vs `qtensor.matmul(x)`). The attention backend is a one-line switch
(`attn_impl="naive"|"flash"`). The Triton kernels in `triton_kernels.py` are the
GPU path; the NumPy engine and the GPU kernels share the same math, validated
against each other on CPU and against PyTorch on GPU.

## Correctness — how we know it's right

`python tests/test_nanollm.py` (CPU):

```
[PASS] tokenizer roundtrip / canonical ids      ( " the" -> [262], "Hello" -> [15496] )
[PASS] flash == naive  (prefill & decode)        rel_err ~1e-8
[PASS] INT8 / INT4 quant round-trip error        3.6e-3 / 6.4e-2
[PASS] KV-cache == no-cache  (identical greedy output)
[PASS] flash-attn model path == naive model path
[PASS] static batch == solo  (per-row identical)
```

`python bench_gpu.py` (GPU) additionally confirms the **Triton kernels** match a
PyTorch reference on a Tesla T4: FlashAttention `rel_err ~1e-7` vs
`F.scaled_dot_product_attention`, and INT8 dequant-matmul exact vs
`(x @ Wq.float()) * scale`.

And `scripts/compare_baseline.py` checks nanollm's logits against **HuggingFace
GPT-2** (when `transformers` is installed) — they match to float32 round-off,
confirming the from-scratch forward pass is the real GPT-2.

## Honesty note (what ran where)

Development was done on a **CPU-only** box, so the NumPy-engine numbers above
(KV-cache, static batching, quantization perplexity/memory) are CPU measurements.

The **Triton GPU kernels** (`triton_kernels.py`) were later executed on a **Tesla
T4** (Kaggle) via `bench_gpu.py`: they compile, run, and match the PyTorch
reference (attention `rel_err ~1e-7`; INT8 dequant-matmul exact) — the *GPU
results* section reports the measured timings. On raw speed those hand-written
**fp32** kernels are competitive with naive baselines but do **not** beat torch's
SDPA / cuBLAS, which use fp16 Tensor Cores and autotuning the kernels don't have
yet. Every number here is reported exactly as measured, wins and losses included.
I don't present GPU numbers I didn't measure.

## Baselines & next steps

- **Correctness baselines:** HuggingFace `transformers` GPT-2 (logit match,
  `scripts/compare_baseline.py`); PyTorch `F.scaled_dot_product_attention` and
  cuBLAS on GPU (`bench_gpu.py`).
- **Performance baselines** (production references the optimizations aim toward):
  `llama.cpp` (`llama-bench`) and `vLLM` (`api_server`).
- **Next steps:**
  - **fp16 `tl.dot` + `@triton.autotune`** so the kernels use the T4's Tensor
    Cores and tuned block sizes — the direct path to closing the gap to SDPA/cuBLAS.
  - continuous batching + paged KV-cache (PagedAttention),
  - quantize the token embedding too (pushes INT8 past 2×→~4× end-to-end),
  - GQA/RoPE to support Llama, and fp16/bf16 activations.
